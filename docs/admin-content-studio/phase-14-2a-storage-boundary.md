# Phase 14.2A Admin Storage boundary

The dedicated Production bucket is `gs://mi-tutora-pro-admin-content` in `US-EAST1` (Standard class, uniform bucket-level access, public access prevention enforced). It is separate from `gs://mi-tutora-pro.firebasestorage.app`; that Firebase bucket's configuration and IAM have not been changed. No objects have been uploaded to the Admin bucket in this phase.

## Current object operations

The Admin server writes immutable `published-content/<type>/<id>/v<version>.json` objects with an `ifGenerationMatch: 0` precondition, downloads them to verify the SHA-256 and to deliver published content, then updates custom object metadata from `CREATING` to `READY`. Firestore version status and the verified artifact hash remain the delivery authority. Admin asset uploads use `ifGenerationMatch: 0`; previews download `admin-content-assets/asset-<uuid>.<extension>`. If the Firestore asset record/audit batch fails after upload, the server deletes that new object as compensating cleanup. There is no object listing or user-facing asset deletion.

Therefore the current implementation requires `storage.objects.create`, `storage.objects.get`, `storage.objects.update` (publication metadata only), and `storage.objects.delete` (failed asset upload cleanup only). It does **not** require `storage.objects.list` or bucket administration. Removing update/delete would change the existing publication/compensation protocol and requires a separate reviewed refactor; it is not assumed safe merely because published object bytes are immutable.

## Production configuration and delivery

The Admin Vercel Production server must set `ADMIN_CONTENT_STORAGE_BUCKET=mi-tutora-pro-admin-content`. The Admin entrypoint uses the Admin-specific WIF profile and requires this exact bucket in Production. Preview remains backend-disabled; local emulator setup may use its emulator bucket. `FIREBASE_STORAGE_BUCKET` remains the existing Firebase bucket for the learner/main deployment and other existing services.

New Firestore publication versions record `artifactBucket` alongside their existing logical `artifactPath`. Versions without that field remain legacy Firebase-bucket versions. The learner site's same-origin `/api/admin-content/public` route continues reading legacy versions locally. For a version explicitly marked with the dedicated bucket, it can delegate the public version read to `https://admin.ycoders.com/api/admin-content/public/<id>/<version>`, where the Admin server verifies published status and artifact hash before returning JSON. Conversely, the Admin Production API delegates legacy-version reads to the existing `https://ycoders.com/api/admin-content/public/<id>/<version>` endpoint, so rollback and Admin-side canonical reads do not need Admin IAM on the Firebase bucket. Both sides check returned version identity and hash, and each routes locally for the bucket it owns; a mismatched bucket fails closed. The learner server never receives Admin Storage IAM permission and the browser never reads the private bucket directly.

The main-site Vercel function is public-read-only in the prepared source. Non-public requests return 404 before credentials or Storage are acquired, so only the Admin project's function can publish or upload assets after a coordinated rollout. Deploy this main-site boundary before enabling Admin writes; the currently deployed main-site function is not yet changed.

After the Admin Production API and domain are live, the learner/main Production server needs `ADMIN_CONTENT_STORAGE_BUCKET=mi-tutora-pro-admin-content` and `ADMIN_PUBLIC_CONTENT_ORIGIN=https://admin.ycoders.com`. Do not set these before the Admin endpoint works. A coordinated deployment/read-only smoke must verify legacy and new versions, including rollback and asset preview. Until then, do not publish new Production content into the dedicated bucket.
